## Las siete ambigüedades del enunciado, resueltas antes de planear

**A-1. ¿Tres componentes hermanos o una página con ramas?** → **Tres componentes hermanos**
seleccionados por una página de veinte líneas. Argumentado con coste de prueba y de captura en
§2.2. La variante «una composición dirigida por datos» también se evaluó y se rechazó, con motivo.

**A-2. ¿De dónde salen las búsquedas recientes, los favoritos y las alertas?** → **Datos de ejemplo
propios**, en `frontend/app/utils/muestrasInicio.ts`. **No se depende de US-006 ni de US-008 para
existir**, pero **sí se les toma el vocabulario** para que un clic lleve a una búsqueda que
devuelve resultados. Verificado con grep: ninguno de los dos planes siembra nada de esto (§2.4).

**A-3. El enunciado afirma que US-006 y US-008 «aún no habrán sembrado nada» cuando esta US se
implemente.** → **Contradice el estado real**: las dos son del mar 11 y esta US es del mié 12, así
que el catálogo **sí** estará sembrado. Lo que es cierto es la conclusión, no la premisa: aunque
estén sembradas, **ninguna de las dos crea tabla ni endpoint de búsquedas recientes, favoritos,
alertas o exportaciones**. Gana el repositorio y queda anotado.

**A-4. ¿Dónde vive el octavo perfil, Ximena Solís, si US-015 decidió no sembrarle usuario?** →
**Espacio `analista`**, documentado, **sin usuario de acceso en S4**. Su perfil consume el portal
por API y US-015 §2.6 lo excluyó del seed con ese motivo. La cobertura que exige el criterio es de
**correspondencia**, no de demostrabilidad con login, y así se declara en el documento en vez de
inventarle un octavo usuario que contradiría el contrato de identidad de US-015 §4.0 C-3.

**A-5. ¿Qué ve un `admin` que abre `/inicio` a mano?** → La **composición operativa**, que es la
más genérica. El espacio `admin` declara `pantallaPrincipal: '/administracion'` y
`composicion: 'operativo'`: un campo, una línea, probado. `/inicio` no se le prohíbe al admin —
prohibir rutas es de US-017 y `/inicio` no está en su lista.

**A-6. ¿La página consulta algo por red?** → **No.** `/inicio` no hace ni un `fetch` en S4. El
buscador es un formulario que navega a `/exploracion?q=<término>`; los resultados viven en la rama
2.2 del mapa de A3 y duplicarlos en `/inicio` sería una segunda superficie de resultados que
habría que diseñar, probar y capturar dos veces. La única dependencia asíncrona es la sesión, y la
carga el middleware de US-017 antes de que la ruta se renderice.

**A-7. ¿Las tres tarjetas del directivo son las tarjetas predictivas de US-026?** → **No.** §26
dice «tarjetas de **indicador**» para US-027 y «tarjetas **predictivas** con etiqueta de método»
para US-026. La frontera semántica es limpia y se adopta: **US-027 muestra el presente** (valor
actual, variación contra el mes anterior, fecha de corte, fuente); **US-026 muestra el futuro**
(proyección con su etiqueta de método) y vive en el tablero. Ningún archivo compartido (§5.4).

### 2.2 Tres componentes hermanos, y no una página con ramas

**Decisión: tres componentes hermanos** —`EspacioOperativo.vue`, `EspacioAnalista.vue`,
`EspacioDirectivo.vue`— que `inicio.vue` selecciona con un `<component :is>`. El argumento es de
coste, no de gusto:

**Coste de prueba.** Un componente hermano se monta con `mount(EspacioOperativo, { props, global:
{ plugins: [i18n, router] } })`: no necesita sesión, ni `useState`, ni `definePageMeta`, ni
`vi.mock`. Con una página llena de `v-if`, **cada** aserción sobre **cualquiera** de las tres
composiciones obliga a montar la página completa y a doblar la sesión antes, con lo que el andamio
se paga tres veces y una regresión en la resolución del rol tiñe de rojo las pruebas de las tres
composiciones a la vez, escondiendo cuál se rompió. Con hermanos, la resolución del rol se prueba
**una vez** sobre una función pura (`espacioDeRol`) y las composiciones se prueban **sin** ella.

**Coste de captura.** Es neutro, y esa es justamente la razón por la que no decide: la figura del
PDF es la pantalla entera a 1440x900 con su barra lateral y su franja de alcance, es decir la
**ruta**, y la ruta es `/inicio` en los tres casos. Lo que sí habría cambiado el coste de captura
es partir `/inicio` en tres rutas —`/inicio/operativo` y compañía—, y eso está **prohibido** por
`pantallas.spec.ts`, que exige exactamente nueve archivos de página y ocho rutas de contrato. Queda
descartado por el repositorio, no por opinión.

**La tercera variante que se evaluó y se rechaza:** una sola composición dirigida por datos, que
recorra `ESPACIOS[rol].bloques` y los pinte en orden. Es más DRY sobre el papel y más cara en la
práctica: las tres composiciones no son la misma rejilla reordenada —el operativo tiene un héroe a
ancho completo, el analista una división en dos columnas y el directivo una rejilla de tres— así
que el recorrido por datos exigiría un mini lenguaje de maquetación (`columnas`, `enfasis`,
`altura`) cuyos únicos tres consumidores son las tres composiciones. Ese lenguaje cuesta más
pruebas que las tres plantillas que sustituye, y una figura de PDF tiene que mostrar **una
disposición concreta**, que una plantilla declara literalmente y un intérprete de datos solo de
forma indirecta.

**Lo que sí es dato y no plantilla:** el **orden y el conjunto de bloques** de cada composición
viven en `utils/espaciosTrabajo.ts`, no en los templates. Así la prueba de orden compara el DOM
contra el contrato en lugar de contra sí misma, y la tabla del documento se genera de la misma
fuente que la pantalla.

### 2.3 La página es un selector de veinte líneas

`inicio.vue` conserva, en este orden y por delante de la composición:

1. `<section :data-ruta="ruta">` — el atributo que `pantallas.spec.ts` verifica.
2. `<h1>{{ titulo }}</h1>` — de `useTituloDeRuta()`, es decir del contrato de navegación.
3. `<p>{{ t('screen.home.description') }}</p>` — el **primer** `<p>` de la página.
4. `<component :is="composicion" :cargando="cargando" :nombre="nombre" />`.

Los puntos 1 a 3 no son decoración: son exactamente lo que mantiene verdes las cinco aserciones de
`pantallas.spec.ts` **sin editar ese archivo**, que es el punto de contención con las dos US
vecinas. Ningún bloque de la composición puede introducir un `<p>` antes del punto 3, y ninguno
puede usar `h1`: todos los títulos de bloque son `h2` y los títulos de tarjeta `h3`.

`screen.home.description` **se reescribe en presente** en los dos catálogos. Hoy dice «Contendrá el
buscador unificado, las búsquedas recientes…», que era cierto cuando la pantalla era un marcador de
posición y deja de serlo el miércoles. Se reescribe en lugar de eliminarse porque la clave sigue
teniendo un consumidor —el propio resumen de la pantalla— y porque borrarla dejaría un hueco en la
paridad de los dos catálogos.

### 2.4 De dónde salen los datos de ejemplo, verificado y no supuesto

`grep -rin "favorit|alerta|reciente"` sobre `docs/us-planning/us-006.md`, `us-008.md` y `us-009.md`
devuelve **una** línea, y trata de días hábiles. La conclusión es firme:

| Bloque | ¿Existe fuente en el repositorio al llegar el mié 12? | De dónde sale |
|---|---|---|
| `recientes` | **No.** Requeriría una tabla `user_search` que ninguna migración crea | Muestra propia |
| `favoritos` | **No.** Requeriría `user_favorite` | Muestra propia |
| `alertas` | **No.** La rama 1.4 del mapa de A3 es faceta transversal sin endpoint en S4 | Muestra propia |
| `exportaciones` | **No.** `create_export_job` es de **US-009, jue 13**, un día *después* de esta US | Muestra propia |
| `indicadores` | **No.** El endpoint de serie preagregada es de US-025, mismo día pero sin contrato publicado | Muestra propia |
| `explorador` (consultas guardadas) | **No** | Muestra propia |

**Decisión: US-027 lleva sus propios datos de ejemplo y no depende de US-006, US-008 ni US-009 para
existir.** Viven en un módulo único, `frontend/app/utils/muestrasInicio.ts`, separado del contrato
de composición a propósito: el contrato es estable y sobrevive a S5; las muestras son desechables y
S5 las sustituye por endpoints borrando **un** archivo.

**Lo que sí se toma de US-006 y US-008, y es lo que hace creíble la demo:** el **vocabulario**. Las
cinco búsquedas recientes son nombres físicos reales del catálogo sembrado —`ratio_lcr`, `sdo_cap`,
`dias_mora`, `nocional_usd`, `mto_disp`— y los favoritos apuntan a códigos de fuente reales
—`liquidez`, `creditos`, `derivados`, `regulatorio`—. Consecuencia concreta: al hacer clic en una
búsqueda reciente, `/exploracion?q=ratio_lcr` **devuelve resultados de verdad** contra el catálogo
de US-008, en vez de una pantalla vacía que delataría el decorado. Es una dependencia de
**contenido**, no de **código**: si el catálogo no estuviera sembrado, la pantalla de inicio se ve
idéntica y solo el destino queda vacío.

**Honestidad de la demo.** Cada bloque con datos de ejemplo lleva una insignia visible
(`workspace.sample.badge`) y el atributo `data-origen="ejemplo"`. La franja de alcance del layout
`portal` ya declara el prototipo en las nueve rutas; la insignia añade el grano fino que el
evaluador necesita para no leer una cifra como institucional.

### 2.5 El reloj es fijo, y eso es una propiedad, no un detalle

Ninguna muestra usa `new Date()` ni `Date.now()`. Todas las fechas son cadenas ISO ancladas a
`INSTANTE_DE_REFERENCIA = '2026-08-12T09:00:00Z'`, y se formatean con
`Intl.DateTimeFormat(idioma, { timeZone: 'UTC', ... })` en `utils/fechas.ts`.

Dos defectos concretos se cierran con esto, y los dos tienen prueba:

1. **Capturas irreproducibles.** Con fechas relativas al reloj, la figura del PDF cambia cada día y
   la recaptura del sábado no coincide con la del miércoles.
2. **Desajuste de hidratación.** `Intl.DateTimeFormat` sin `timeZone` usa la zona del proceso: el
   servidor de Nuxt y el navegador del lector pueden diferir, y Vue reporta un *hydration
   mismatch* en cada fecha renderizada. Fijar UTC lo elimina de raíz.

import type { RolUsuario } from '~/types/sesion'   // US-015

/** The four workspaces. One per role, no more and no fewer. */
export type ClaveEspacio = RolUsuario

/** The three compositions of /inicio. The admin workspace is a different route. */
export type ClaveComposicion = 'operativo' | 'analista' | 'directivo'

/** Ordered blocks a composition can render. */
export type ClaveBloque =
  | 'buscador' | 'recientes' | 'favoritos' | 'alertas'
  | 'perfil' | 'explorador' | 'exportaciones' | 'indicadores'

/** How much room the unified search takes in a composition. */
export type EnfasisBuscador = 'dominante' | 'normal' | 'reducido'

export type TonoInsignia = 'neutro' | 'exito' | 'atencion' | 'peligro'

export interface EspacioTrabajo {
  readonly clave: ClaveEspacio
  /** Route the user lands on after signing in. */
  readonly pantallaPrincipal: string
  /** Composition rendered when the user opens /inicio. */
  readonly composicion: ClaveComposicion
  /** Blocks in render order, which is also keyboard focus order. */
  readonly bloques: readonly ClaveBloque[]
  readonly enfasisBuscador: EnfasisBuscador
}

export interface InsigniaLista {
  readonly claveTexto: string
  readonly tono: TonoInsignia
}

export interface ElementoLista {
  readonly id: string
  /** Translation key of the visible label. Never a literal sentence. */
  readonly claveEtiqueta: string
  /** Contract route, with query string when it carries a search term. */
  readonly destino: string
  /** ISO instant anchored to INSTANTE_DE_REFERENCIA. Never Date.now(). */
  readonly fecha?: string
  readonly insignia?: InsigniaLista
}

export interface Indicador {
  readonly id: string
  readonly claveEtiqueta: string
  readonly valor: number
  readonly unidad: 'porcentaje' | 'millones-mxn' | 'dias'

  readonly variacion: number
  readonly fecha: string
  readonly destino: string
}

3. **Paridad exacta de conjuntos de claves.** Añadir en un solo catálogo degrada el inglés en
   silencio.

vi.stubGlobal('useState', <T>(_clave: string, iniciar?: () => T) => ref(iniciar?.() as T))

`/inicio` **permanece** en la lista de rutas con andamiaje que US-015 introduce

aserciones que esa lista gobierna siguen siendo ciertas y **no hay que encoger la lista**. Es la
consecuencia práctica de la decisión de §2.3, y es lo que reduce la contención sobre el archivo
compartido a una sola línea condicional.
