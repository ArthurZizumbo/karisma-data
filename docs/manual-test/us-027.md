# Pruebas manuales — US-027 (Espacios de trabajo por rol)

**SHA base**: `25dac56` · **Rama**: `us-027` · **Fecha**: 12-ago-2026

Aquí está solo lo que la suite **no** puede demostrar. Las 489 pruebas del frontend doblan `$fetch`,
`useState`, el enrutador y el evento de h3: ninguna abre un socket ni pinta píxeles, así que miden
que cada pieza hace lo suyo y no pueden medir ni **cómo se ve la pantalla a 1440 px** ni **qué llega
en el HTML que el servidor sirve**. Lo mecánicamente verificable —el contrato de composición, el
orden de los bloques, los estados vacío y cargando, la paridad de los dos catálogos, el destino de
cada rol— ya lo cubren `test/espaciosTrabajo.spec.ts`, `test/inicio.spec.ts` y `test/sesion.spec.ts`
y **no se repite aquí**.

Requisito previo: entorno levantado (`db` y `api` en Docker, frontend en `pnpm dev`) y
`DEMO_LOGIN_ENABLED` encendida. La contraseña compartida de los siete usuarios sembrados vive en
`backend/.env.local` bajo `KARISMA_DEMO_PASSWORD` y **no se escribe en este archivo**.

---

## 1. Los cuatro espacios, en un solo comando

```bash
bash scripts/capturar_espacios.sh
```

Acuña una sesión de demostración por perfil, pide la pantalla principal de cada uno y comprueba en el
**cuerpo HTTP** que la composición servida es la esperada, más el quinto caso —el administrador que
abre `/inicio` a mano—. Sale distinto de cero al primer fallo.

Salida esperada, que es la evidencia que se pega en el PR:

```
  OK   operativo  /inicio          composicion operativo
  OK   analista   /inicio          composicion analista
  OK   directivo  /inicio          composicion directivo
  OK   admin      /administracion  pantalla propia del perfil
  OK   admin      /inicio          recae en la composicion operativo

4/4 espacios verificados
```

Que la marca `data-espacio` esté en el HTML del servidor y no sólo después de hidratar es lo que
importa: si la composición se resolviera en el navegador, la captura del informe saldría vacía y
esta comprobación sería la única que lo vería.

**Si `DEMO_LOGIN_ENABLED` está apagada**, el guion falla con un mensaje que lo dice, en vez de
producir cuatro fallos de ruta que parecerían un portal roto.

## 2. Las tres composiciones se ven distintas de verdad

Con el navegador a **1440 × 900** —el ancho de captura de las figuras del informe—, entrar
sucesivamente como `lmendez`, `dhernandez` y `acastaneda` y abrir `/inicio`.

| # | Qué mirar | Esperado |
|---|---|---|
| 2.1 | `lmendez` | El buscador ocupa el ancho completo y es lo primero bajo el encabezado. Debajo, dos columnas con recientes, favoritos, alertas y perfil |
| 2.2 | `dhernandez` | Arriba, consultas guardadas y exportaciones. El buscador aparece **después**, en tamaño normal |
| 2.3 | `acastaneda` | Tres tarjetas de cifra en rejilla, **completas y sin recorte**, antes de cualquier otra cosa. El buscador es una línea |
| 2.4 | Las tres | La franja de alcance del prototipo sigue arriba y la barra lateral no cambia entre perfiles salvo por lo que US-017 oculta |

**Por qué no se automatiza**: la maquetación exacta es justo lo que US-UX-07 puede recomponer el
sábado para las figuras; fijar el marcado en una prueba sería deuda que se borra en el primer cambio
real. Lo que sí está probado es el **orden**, que es el criterio de aceptación.

## 3. El aterrizaje después de entrar

| # | Acción | Esperado |
|---|---|---|
| 3.1 | Entrar como `lmendez` | Aterriza en `/inicio`, composición operativa |
| 3.2 | Entrar como `dhernandez` | Aterriza en `/inicio`, composición analista |
| 3.3 | Entrar como `acastaneda` | Aterriza en `/inicio`, composición directiva |
| 3.4 | Entrar como `movalle` | Aterriza en **`/administracion`**, no en `/inicio` |

Este bloque es el que cambia respecto de US-015 y por eso se verifica a mano: antes el analista
aterrizaba en `/exploracion` y el directivo en `/exploracion/tableros`, con lo que **ninguno de los
dos veía nunca la composición que esta US construye para ellos**.

## 4. Ningún atajo lleva a una puerta cerrada

| # | Acción | Esperado |
|---|---|---|
| 4.1 | Como `lmendez`, pulsar cada enlace de la pantalla | Todos abren. Ninguno responde 403 ni muestra el estado «sin permiso» |
| 4.2 | Como `dhernandez`, pulsar una exportación reciente | Abre `/exploracion/exportar` sin refusal |
| 4.3 | Como `acastaneda`, pulsar «Ver en el tablero» de una tarjeta | Abre `/exploracion/tableros` sin refusal |
| 4.4 | En cualquiera de las tres | **No aparece ningún enlace a Administración** dentro de la composición |

Cruza con el ocultamiento por rol de US-017; una prueba unitaria que lo repitiera duplicaría su
matriz de permisos en vez de comprobar nada nuevo.

## 5. Recorrido de teclado

Con `lmendez` en `/inicio` y sin tocar el ratón:

| # | Acción | Esperado |
|---|---|---|
| 5.1 | Primer `Tab` desde la carga | Aparece «Saltar al contenido» |
| 5.2 | `Enter` sobre él y `Tab` de nuevo | El foco cae dentro del contenido, y el **campo de búsqueda es el primer elemento enfocable** de la composición |
| 5.3 | Escribir un término y `Enter` | Navega a `/exploracion?q=<término>` sin recargar la página |
| 5.4 | Seguir tabulando | El anillo de foco es visible en todos los enlaces de las listas; no hay ninguna trampa de foco |

Exige navegador real: el orden de foco es el orden del DOM más lo que el navegador decide con los
elementos deshabilitados, y `happy-dom` no simula ninguna de las dos cosas.

## 6. Sin salto de maquetación al resolver la sesión

Con la pestaña de red del navegador limitada a «3G lento», recargar `/inicio`.

| # | Qué mirar | Esperado |
|---|---|---|
| 6.1 | Durante la carga | Las listas ya ocupan su altura final, con filas en gris; el saludo mantiene su línea |
| 6.2 | Al llegar la sesión | El contenido sustituye a los marcadores **sin que nada se desplace** |
| 6.3 | Consola | 0 errores y **0 avisos de hidratación**, en particular ninguno sobre fechas |

El punto 6.3 es el que justifica el `timeZone: 'UTC'` de `utils/fechas.ts`: sin él, el servidor y el
navegador formatearían el mismo instante de forma distinta y Vue reportaría un desajuste en cada
fecha.

## 8. Correspondencia con el guion de Playwright del sábado

US-UX-07 necesita tres figuras de la Pantalla 1 para el PDF. Su guion son **los mismos cuatro pasos**
que este archivo automatiza, y se escriben aquí para que el sábado no se invente otra cosa:

```
para rol en (operativo, analista, directivo):
    request.post('/api/auth/demo', { data: { rol } })
    page.goto('/inicio')
    page.wait_for_selector('[data-espacio="<composicion>"]')
    page.screenshot(path=f'figura-inicio-{rol}.png', full_page=False)   # 1440x900
```

`scripts/capturar_espacios.sh` queda como su especificación ejecutable y como comprobación de humo
cuando no hay navegador instalado.

## Anotaciones del entorno, verificadas el 12-ago-2026

- **`GET /api/catalog/search` todavía no existe** en el backend (`/openapi.json` publica cuatro
  rutas: las tres de sesión y `/health`). El destino de una búsqueda reciente, `/exploracion?q=…`,
  abre correctamente la pantalla de exploración —que sigue siendo andamiaje declarado— con el
  término en la barra de direcciones. El vocabulario de las muestras **sí** está sembrado: los cinco
  nombres físicos y los cuatro códigos de fuente aparecen en `db/seeds/catalog.sql`. Cuando la rama
  2.2 aterrice, el clic devolverá filas sin tocar esta US.
- **La API no corre nativa en Windows**: psycopg rechaza el `ProactorEventLoop` que uvicorn usa por
  omisión ahí. Se levanta `api` en Docker.
- **`localhost` no es `127.0.0.1`** para Node 25: resuelve primero a `::1`. Con el `api` de Compose
  no ocurre; con una API en el host, arrancar el frontend con `NUXT_API_BASE=http://127.0.0.1:8000`.
